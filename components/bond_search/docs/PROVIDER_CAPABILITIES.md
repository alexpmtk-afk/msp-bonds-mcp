# Состояние загрузчиков официальных источников

Проверено 15 ноября 2026 года. Этот документ описывает только возможности компонента bond_search; он не содержит правил отбора конкретных бумаг, идентификаторов пользовательских таблиц или данных портфеля.

## Реализовано

### MOEX ISS — точная проверка ISIN

Компонент сначала выполняет точный поиск по ISIN. Если он не возвращает точную строку, компонент может вручную и ограниченно просмотреть страницы официального списка облигаций ISS. Используются `start`, `limit` и блок `securities.cursor`; записываются обследованные диапазоны, число страниц и строк, общий объём и признак полного обхода. 45-секундный бюджет проверяется перед каждым обращением, число страниц ограничено 20, тайм-аут одного HTTP-обращения не превышает 10 секунд. Поскольку запрос синхронный, уже начатое обращение может завершиться после бюджета; новых обращений после его исчерпания не начинается.

Совпадение точного ISIN подтверждает только наличие идентификатора в полученной записи MOEX. Если список неполон, курсор отсутствует или диапазоны страниц не согласуются, отрицательный ответ имеет состояние `INCONCLUSIVE`. Только полностью пройденный снимок может вернуть `NOT_FOUND_IN_SCANNED_RESULTS`; это означает отсутствие только в обследованном списке, не во всей базе MOEX.

Для транспортного сбоя доступны коды этапа: DNS, TLS, соединение, HTTP-статус, чтение ответа и разбор JSON. Повтор для этой диагностики не превышает одной попытки на страницу. Размер ответа ограничен. Ошибка или тайм-аут не преобразуются в отрицательный факт.

Запросы к MOEX остаются ручной диагностикой. Программная периодическая загрузка или сбор для последующего коммерческого применения не включены; перед таким режимом требуется отдельно проверить применимые условия использования и договорные ограничения.

[Документация MOEX ISS](https://www.moex.com/a2920) описывает общедоступные справочные данные и задержанные рыночные данные. [Условия использования сведений ISS](https://www.moex.com/a2193) ограничивают их ознакомительными целями; иное использование требует отдельного договора с Московской биржей.

## Пока только ручная проверка

| Проверка | Официальный источник | Текущее ограничение |
|---|---|---|
| Кредитный рейтинг и действия агентства | [Репозитарий Банка России](https://ratings.cbr.ru/) | Веб-поиск доступен; автоматический запрос через документированный открытый интерфейс пока не подтверждён. |
| Юридические условия купона и оферты | Решение о выпуске, официальный сайт эмитента, данные НРД | Рыночное поле или найденная дата выплаты не заменяют первичный документ выпуска. |
| Амортизация и погашение | [Страница MOEX по облигациям](https://www.moex.com/ru/bondization) и решение о выпуске | До программного разбора первичного источника график не считается проверенным. |
| Банкротство и дефолтные события | [Федресурс](https://fedresurs.ru/), [Картотека арбитражных дел](https://kad.arbitr.ru/) | Результат поиска должен быть проверен по официальной записи; неполный поиск не трактуется как отсутствие событий. |
| Финансовая отчётность эмитента | [Ресурс БФО ФНС](https://bo.nalog.gov.ru/) | Публичный веб-поиск доступен; REST API ФНС предоставляется по подписке. У компонента нет настроенного доступа к этому API. |

## Google Workspace

Чтение вкладок «логика поиска» и «ресурсы поиска» подключается к функции msp_bonds_google.workspace.sheets_read уже установленного компонента Google Workspace. Компонент поиска не хранит второй OAuth-токен, не запускает вход в Google и не пишет в таблицу. Если штатная запись доступа отсутствует в Windows Credential Manager, чтение завершится явным статусом EXISTING_DRIVE_CREDENTIAL_MISSING.

## Рейтинги и юридические условия выпуска

`manual_sources.py` принимает вручную перенесённые поля рейтинга или решения о выпуске с названием официального источника, URL, временем получения, датой документа и местом в документе. Код не загружает страницы и не извлекает данные сам: URL необходимо брать из доверенного реестра ресурсов, а запись сверять вручную. Заполненные поля получают только `UNVERIFIED`; пустые обязательные поля получают `MISSING`. Поэтому этот захват сам по себе не может закрыть этап проверки.

## Принцип обработки пробелов

Неизвестное значение остаётся неизвестным. Ошибка сети, пустой ответ, неполная страница, недоступный официальный интерфейс или отсутствие документа не преобразуются в ноль, отрицательный факт либо подтверждённое значение. Полная последовательная проверка и подключение к основному MCP не включены.
