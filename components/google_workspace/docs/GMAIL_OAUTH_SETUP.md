# Gmail OAuth для локального MCP

Инструкция описывает существующий компонент Google Workspace. Она не создаёт OAuth-клиент и не меняет Google Cloud.

## Подтверждённое состояние HOME

21 ноября 2026 года владелец сообщил, что в обычной среде HOME сохранённые Gmail-учётные данные загрузились, однократная проверка users.getProfile завершилась PASS с кодом 0, Gmail API включён, а разрешение равно gmail.readonly.

Проверка исходников подтвердила цепочку service_client() → load_credentials(). Отдельная локальная проверка stdio обнаружила 18 инструментов и подтвердила совпадение имён и входных схем с локальной фикстурой. Она не читала учётные данные и не обращалась к Google. В рамках этой задачи живой вызов users.getProfile повторно не выполнялся.

Публичная ветка main содержит отдельный снимок кода и 17 инструментов. Не считать её счётчик инструментов состоянием локальной установки HOME.

## Проверка сохранённой авторизации

Из корня MCP-проекта запустите:

    python -B -m msp_bonds_google.cli status

Строка Gmail показывает наличие записи в Windows Credential Manager и требуемое компонентом разрешение. Это только проверка наличия: она не проверяет срок действия токена, не обновляет его и не вызывает Gmail API.

Инструмент MCP google_oauth_status также проверяет только локальную запись. Он не подтверждает, что Gmail API принимает токен, и не возвращает значения учётных данных.

## Первоначальный вход Gmail

Браузерное подтверждение выполняет только владелец аккаунта. Файл Desktop OAuth JSON должен оставаться вне репозитория; не отправляйте его содержимое в чат.

В одной PowerShell-сессии задайте MSP_GOOGLE_OAUTH_CLIENT как путь к локальному OAuth JSON и выполните:

    $env:MSP_GOOGLE_OAUTH_CLIENT = '<полный локальный путь к OAuth JSON>'
    python -B -m msp_bonds_google.cli login gmail
    Remove-Item Env:MSP_GOOGLE_OAUTH_CLIENT -ErrorAction SilentlyContinue

Замените заглушку локальным путём, известным владельцу. Компонент запрашивает доступ офлайн только с правом Gmail на чтение, затем сохраняет данные через Windows Credential Manager. Вызов Python напрямую не требует менять политику запуска сценариев PowerShell. Не передавайте файл, секрет клиента, пароль или токен другим лицам.

Не выполняйте login gmail_write для этой задачи.

## Обычное обновление токена

Ежедневный ручной вход не требуется, пока сохранённый refresh token действителен и сеть может связаться с Google. Инструменты Gmail получают API-клиент через service_client(), который вызывает load_credentials(). При истёкшем access token и наличии refresh token библиотека Google Auth запрашивает новый токен, после чего компонент сохраняет обновлённую запись через keyring в Windows Credential Manager. Действительный access token используется повторно. Обновление выполняется по запросу, не в фоне.

Если refresh token отозван, отсутствует или отклонён, потребуется новый вход, одобренный владельцем. Сетевую ошибку нужно диагностировать как проблему связи; не обходите и не меняйте прокси или защитные настройки.

## Безопасная проверка Gmail API без чтения писем

Для живого запроса требуется отдельное разрешение владельца. Запустите:

    python -B -m msp_bonds_google.gmail_profile_diagnostic

Если access token не истёк, команда выполняет ровно один GET users.getProfile(userId="me"). Тело ответа не читается; адрес почты не показывается; поиск писем и изменения не выполняются. Команда печатает только PASS или ERROR. Диагностика намеренно не обновляет токен: просроченный токен даёт код 6 до сетевого запроса. Обычный путь MCP обновляет токен до создания Gmail-клиента.

Коды завершения:

- 2 — ошибка чтения защищённого хранилища.
- 3 — запись Gmail-авторизации отсутствует.
- 4 — разрешение не совпадает с Gmail readonly.
- 5 — запись токена некорректна.
- 6 — access token истёк; эта диагностика не обновляет его.
- 11 — Gmail ответил HTTP 401.
- 12 — Gmail ответил HTTP 403; проверьте доступность API, согласие и ограничения сервиса.
- 13 — другой HTTP-ответ Gmail.
- 14 — тайм-аут сети.
- 15 — общая ошибка передачи данных.

Код 15 не различает DNS, TLS, прокси и отказ соединения. TransportError при обновлении также указывает на сетевую передачу, но не устанавливает её точную причину. Локальная проверка сети или прокси может сузить причину без Gmail-токена; не меняйте сетевые настройки в ходе диагностики.

## Разрешения и границы

- Для Gmail используется https://www.googleapis.com/auth/gmail.readonly.
- Не читать письма или вложения без отдельной прямой задачи.
- Не менять письма, ярлыки, настройки Gmail, файлы Drive или таблицы.
- Не использовать gmail.modify и инструменты записи Gmail для задачи только на чтение.
- Не сохранять и не публиковать OAuth JSON, токены, секрет клиента, адрес аккаунта или финансовые данные.
- Автоматические тесты используют только синтетические данные и подмены; они не открывают настоящее защищённое хранилище и не вызывают Google.

Для изменения прав, OAuth-клиента, хранилища или настроек Google Cloud требуется отдельное решение владельца.
